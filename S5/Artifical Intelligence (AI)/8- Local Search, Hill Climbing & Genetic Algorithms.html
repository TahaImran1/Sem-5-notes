1Local Search & Hill Climbing Foundations

Lecture 11: Beyond classical path-based search, landscape topography, greediness, and escaping failure modes

Real-World Intuition: Why Throw Away the Path?

Imagine planning a road trip from Lahore to Islamabad. Every turn, toll booth, and highway exit matters. That is Classical Search (BFS, DFS, A*). The solution is the path itself.

Now imagine designing the layout of an integrated circuit chip with 5 billion transistors, or assigning classrooms to 500 university courses. Does anyone care in what sequence you placed the rooms on your scratchpad? No. The sequence of steps is completely irrelevant. The final configuration alone is the solution.

Critical Thinking: Classical search requires storing every path in an OpenList. On massive problems, your computer's RAM crashes within seconds. Local Search solves this by keeping only one state in memory at any time. It asks: "Can I make a small tweak to my current guess to make it slightly better?"

Jargon Demystified — Local Search: An algorithm that operates by making small, iterative changes to a single complete candidate solution, keeping only the current state in memory (O(1) space).

Jargon Demystified — State-Space Landscape: A topological surface where horizontal coordinates represent complete problem configurations and vertical elevation represents solution quality.

Jargon Demystified — Objective Function: A scoring function where higher elevation equals better quality (used in maximization problems).

Jargon Demystified — Cost / Heuristic Function (h): A penalty function where lower elevation equals better quality (used in minimization problems).

Systematic Search vs. Local Search Comparison

Feature Systematic Search (BFS, DFS, A*) Local Search (Hill Climbing, GA)
Memory Requirement Exponential (O(b^d)) — keeps entire search frontier. Constant (O(1)) — keeps only current state or small population.
Solution Definition The path from start state to goal. The goal state configuration itself (path is discarded).
Search Space Suitability Finite, discrete state graphs. Massive, continuous, or infinite state spaces.
Typical Problems Routing, GPS Navigation, 8-Puzzle, Maze Solving. N-Queens, VLSI Chip Layout, Job Scheduling, ML Parameter Tuning.

The Hill-Climbing Algorithm (Steepest Ascent)

Hill climbing is famously described as: "Like climbing Mount Everest in thick fog with amnesia."

  • Thick Fog: The algorithm cannot look ahead to see the distant summit; it can only feel the gradient of immediate neighbors.
  • Amnesia: It keeps no search history; it cannot remember where it came from or backtrack when trapped.
Algorithm: Steepest-Ascent Hill Climbing 1. current = INITIAL-STATE(problem) 2. loop do: neighbor = highest-valued successor of current if neighbor.VALUE <= current.VALUE then: return current.STATE (Peak reached; terminate) current = neighbor

Detailed Solved Example: 8-Queens via Hill Climbing

Problem: Place 8 queens on an 8 x 8 board such that no two queens attack each other along any row, column, or diagonal.

State Representation: An array of length 8 where Index = Column and Value = Row. Exactly one queen per column.

Heuristic Cost Function (h): The number of pairs of queens attacking each other directly or indirectly. The goal is h = 0. Total possible pairs of queens = Combination(8, 2) = (8 * 7) / 2 = 28.

The 4 Classical Pathologies of Hill Climbing

1. LOCAL MAXIMUM 2. FLAT PLATEAU 3. RIDGE ▲ ┌────────────┐ / \ / \ / \ / \ ◄── Crest slopes up / \ / \ / \ [All neighbors worse] [All neighbors equal] [Orthogonal steps fall off]
  • Local Maximum: A peak that is higher than all its neighbors, but lower than the global maximum. The algorithm sees only downward moves and freezes prematurely.
  • Flat Plateau: A flat region of the state space where all neighboring states have the exact same value. The algorithm has no gradient to guide it and wanders aimlessly.
  • Shoulder: A flat plateau that actually adjoins an upward slope. Terminating too early causes the algorithm to miss the ascending terrain.
  • Ridge: A sequence of local maxima joined together. The crest slopes gently uphill, but the sides drop steeply. Because standard hill climbing only adjusts one variable at a time (moving along orthogonal grid axes), every single neighboring move drops downhill, trapping the search.

Hill Climbing Variants

Variant Neighbor Selection Rule Convergence Speed Completeness
Simple Hill Climbing Evaluates neighbors sequentially; accepts the first neighbor that is better than the current state. Very Fast per step Incomplete (easily stuck)
Steepest Ascent Evaluates all neighbors; selects the neighbor with the maximum improvement. Moderate Incomplete
First-Choice Generates neighbors at random; accepts the first one that is strictly better. Essential when branching factor is huge. Fast Incomplete
Stochastic Chooses randomly among uphill moves; probability of selection is proportional to steepness. Slow Incomplete
Random-Restart Runs repeated independent hill-climbing searches from randomly generated starting states. Keeps the best result found. Variable Complete with probability → 1

Exam Fact: Sideways Moves & Massive Scaling

A sideways move is an escape step to a neighbor with identical heuristic value (h_neighbor = h_current). To prevent infinite loops, a limit (usually 100 consecutive sideways moves) is enforced.

With sideways moves and random restarts, hill climbing can solve 3 million queens in under 1 minute!

2Genetic Algorithms I: Biologically Inspired Computing & Representation

Lectures 12 & 13, Luger 12.0–12.1.2: Darwinian foundations, chromosome encoding, genetic operators, and worked traces

Real-World Intuition: The Power of Sexual Recombination

Why did sexual reproduction evolve in nature instead of just asexual cloning?

Imagine an organism that develops a brilliant immune defense against virus X, but has poor eyesight. In a different part of the forest, another organism has razor-sharp eyesight, but is vulnerable to virus X. With asexual cloning (like hill climbing mutation), combining those two superpowers takes millennia of lucky mutations.

With Crossover (Sex), they mate, and their offspring immediately inherits both the razor-sharp vision and the virus immunity in a single generation! Genetic Algorithms mimic this exact principle to combine partial solutions from different regions of the search space.

Jargon Demystified — Gene: The basic unit of heredity representing a single parameter or feature of a candidate solution.

Jargon Demystified — Allele: The specific setting or value assigned to a gene (e.g., bit `1` or `0`, or real number `4.5`).

Jargon Demystified — Chromosome: An ordered string of genes representing a complete candidate solution point in the search space.

Jargon Demystified — Genotype vs. Phenotype: The genotype is the internal encoded string (e.g., bit string `1010`). The phenotype is the decoded real-world physical behavior (e.g., a cookie recipe with 10g sugar, 0g flour).

Jargon Demystified — Epistasis: Non-linear interaction between genes where the fitness contribution of one gene depends entirely on the value of another gene.

The Canonical Genetic Algorithm Loop

[Start: t = 0] ──► [Initialize Random Population P(t)] │ ▼ ┌──► [Evaluate Fitness of each member] │ │ │ ▼ │ [Check Termination Condition] ──(Yes)──► [Return Best Solution] │ │ (No) │ ▼ │ [Select Parents based on Fitness] │ │ │ ▼ │ [Perform Crossover (Offspring)] │ │ │ ▼ │ [Apply Mutation with rate p_mu] │ │ │ ▼ │ [Replace population: P(t+1)] │ │ └─────────────┘

The 8 Basic Attributes of a Genetic Algorithm

  1. Genetic Representation (Encoding): Binary strings, real-valued vectors, or permutations.
  2. Population Size (P):
    • Too large: Excessive CPU evaluation time; slow convergence.
    • Too small: Lack of genetic diversity; triggers Premature Convergence where the entire population collapses into identical suboptimal clones.
  3. Fitness (Evaluation) Function: A mathematical metric evaluating how well a chromosome solves the problem.
  4. Genetic Operators: Crossover (recombination) and Mutation (random variation).
  5. Selection Algorithm: Strategy for choosing parents based on fitness.
  6. Generation Gap: Fraction of current population replaced in each generation.
  7. Amount of Elitism: Fraction of top-tier individuals guaranteed to survive unmodified.
  8. Number of Duplicates Allowed: Policy on permitting identical chromosomes.

3Genetic Algorithms II: Selection Mechanics & Population Dynamics

Lectures 14 & 15, Luger 12.1.3: Selective pressure, rank selection, diversity, generation gap, and 8-queens/knapsack traces

Real-World Intuition: The Selective Pressure Dilemma

Imagine a school that gives all scholarships exclusively to the single student who scores highest on day one, immediately expelling all others. The school collapses into a monoculture with zero intellectual diversity. If someone gets sick, the school fails.

Now imagine a school that hands out grades completely at random. Students have no incentive to study, and no knowledge is accumulated.

Selective Pressure is the degree to which better fitness is favored:

  • Too High: One decent candidate dominates immediately. The population rapidly converges to a clone army stuck at a mediocre local peak.
  • Too Low: Evolution degrades into a random, blind search.

Jargon Demystified — Selective Pressure: The rate at which above-average individuals are selected as parents over below-average ones.

Jargon Demystified — Generation Gap (G): The fraction of the current population that is replaced by new offspring in each generation.

Jargon Demystified — Elitism: The strategy of copying the top k fittest chromosomes directly into the next generation without modification, guaranteeing that the best solution never regresses.

1. Roulette Wheel (Fitness-Proportionate Selection)

Selection probability is directly proportional to fitness:

p_i = f_i / (Sum of f_j from j=1 to P)
Chromosome (i) Fitness (f_i) Selection Probability (p_i) Roulette Wheel Arc (Degrees)
1 7 7 / 14 = 0.500 (50.0 percent) 180.0 deg
2 4 4 / 14 = 0.286 (28.6 percent) 102.9 deg
3 2 2 / 14 = 0.143 (14.3 percent) 51.4 deg
4 1 1 / 14 = 0.071 (7.1 percent) 25.7 deg
Total 14 1.000 (100 percent) 360.0 deg

Roulette Wheel Weaknesses

  • Early Stage: If one chromosome has fitness 10x higher than others, it takes over the entire population in 2 generations (premature convergence).
  • Late Stage: When all chromosomes have close fitness (e.g. 995, 996, 998), the probabilities become almost identical (25 percent each). Selective pressure drops to zero precisely when fine-grained optimization is needed.

2. Linear Rank Selection

Sorts the population from worst (r = P) to best (r = 1). Reassigns fitness based strictly on rank, completely immunizing the search against raw fitness scaling!

Formula 1 (Standard Rank): New Fitness(r) = (P - r) + 1 Formula 2 (User-Controlled Slope with min and max): New Fitness(r) = (P - r) * [(max - min) / (P - 1)] + min

Example with P = 11, max = 8, min = 3:
Slope = (8 - 3) / (11 - 1) = 5 / 10 = 0.5.
• Rank 1 (Best): (11 - 1) * 0.5 + 3 = 8.0
• Rank 6 (Median): (11 - 6) * 0.5 + 3 = 5.5
• Rank 11 (Worst): (11 - 11) * 0.5 + 3 = 3.0

3. Tournament Selection

Pulls a random subset of b individuals from the population. The individual with the highest fitness in that subset wins. Setting b = 2 (Binary Tournament) is standard in production.

4. The Diversity Principle: Survival of the Most Diverse

In many fitness landscapes, an individual with slightly lower fitness that explores an entirely new, unvisited region is far more valuable than a high-fitness individual clustered next to existing solutions.

Diversity_i = Sum of Distance(i, j)^2 for all j in Selected Combined Rank = Rank_Quality + Rank_Diversity
Solved Exam Problem: Generation Gap & Elitism FAST-NU Exam Trap

Exam Problem: "In a Genetic Algorithm, a generation has 50 chromosomes, out of which the 5 fittest ones are placed in the next generation without any competition from the offspring. The rest of the 45 chromosomes of the next generation are chosen from the pool of parents and offspring. Suppose 30 chromosomes of the offspring make it to the new generation. What is the generation gap and what is the elitism value? Duplicates are not allowed."

Step-by-Step Formal Solution
  1. Elitism Value (E): Elitism is the proportion of top-tier individuals guaranteed survival without competition.
    E = Guaranteed Elite Individuals / P = 5 / 50 = 0.10 (10 percent)
  2. Generation Gap (G): The generation gap is the fraction of the population that is replaced by offspring in the next generation.
    G = Offspring entering Next Generation / P = 30 / 50 = 0.60 (60 percent)
  3. Population Verification: Elite Parents = 5 | Non-elite Surviving Parents = 15 | Offspring = 30 → Total = 50!

Permutation Problems: Traveling Salesperson Problem (TSP)

Standard single-point crossover fails on permutation problems because it generates illegal tours (duplicate and omitted cities):

Parent 1: (1 2 3 │ 4 5) Parent 2: (3 5 4 │ 1 2) Child: (1 2 3 │ 1 2) ◄── ILLEGAL! Cities 1 & 2 duplicated; 4 & 5 missing!

Specialized Permutation Crossover Operators:

  • Partially Mapped Crossover (PMX): Copies an intermediate swath from Parent 1 to Child 1, creates a positional mapping between parent swaths, and fills remaining slots from Parent 2 using the mapping to resolve duplicates.
  • Order Crossover (OX): Copies an intermediate swath from Parent 1, then fills the remaining slots using the unused cities in the exact sequential order they appear in Parent 2.
  • Cycle Crossover (CX): Preserves the exact absolute city index positions by identifying alternating cycles between the two parents.
  • Inversion Mutation: Reverses a sub-sequence of cities between two randomly chosen points in the tour (e.g., (1, 2 | 3, 4, 5 | 6, 7) → (1, 2 | 5, 4, 3 | 6, 7)), removing path crossing loops in Euclidean space!

4Theoretical Foundations: Holland's Schema Theorem

Luger 12.1.4: Implicit parallelism, schema anatomy, mathematical derivation, and the Building Block Hypothesis

Real-World Intuition: Implicit Parallelism

How can a Genetic Algorithm evaluate only 50 candidate chromosomes in a generation, yet effectively search an astronomically huge search space of 2^100 possible states?

John Holland proved that when you evaluate a single chromosome, you are not just evaluating one solution. You are simultaneously sampling every single sub-pattern contained inside that chromosome! A single string of length L contains 2^L sub-patterns. Evaluating P chromosomes processes between P^3 and O(P * 2^L) sub-templates concurrently with zero extra compute. This miracle is called Implicit Parallelism.

Jargon Demystified — Schema (plural: Schemata): A pattern template describing a subset of bit strings, constructed over the ternary alphabet {0, 1, *}, where * represents a wildcard ("don't care").

Jargon Demystified — Order o(H): The number of fixed (defined) positions (0 or 1) in schema H.

Jargon Demystified — Defining Length delta(H): The distance between the first fixed bit and the last fixed bit in schema H.

Order vs. Defining Length Examples

Schema (H) Order o(H) First Fixed Index Last Fixed Index Defining Length delta(H) Resistance to Crossover
[* 1 * * 0 *] 2 2 5 5 - 2 = 3 High (Short length)
[1 1 0 * 0 1] 5 1 6 6 - 1 = 5 Very Low (Vulnerable)
[* * * 1 0 *] 2 4 5 5 - 4 = 1 Extremely High
[0 * * * * 1] 2 1 6 6 - 1 = 5 Extremely Low

Rigorous Mathematical Derivation of the Schema Theorem

Holland's Schema Theorem Step-by-Step Derivation Core Theoretical Proof

Let m(H, t) be the expected number of instances of schema H at generation t. Let f(H) be the average fitness of instances of H, and avg_f be the average population fitness.

Step 1: Effect of Fitness-Proportionate Selection

The probability that an instance of H is chosen in roulette wheel selection is:

P(selection) = f(H) / (Sum of f_j) = f(H) / (P * avg_f)

Across P independent parent selection trials, the expected count becomes:

m(H, t)_selected = P * [ m(H, t) * (f(H) / (P * avg_f)) ] = m(H, t) * (f(H) / avg_f)

Conclusion: If a schema has above-average fitness (f(H) > avg_f), its representation grows exponentially!

Step 2: Effect of Single-Point Crossover Disruption

A chromosome has L - 1 possible cut points. Crossover disrupts schema H only if the cut point falls between the first and last fixed bits.

P(cut falls inside H) = delta(H) / (L - 1)

Accounting for the crossover probability p_c, the lower bound on schema survival is:

S_c >= 1 - p_c * [delta(H) / (L - 1)]

Conclusion: Schemata with small defining length delta(H) have near-zero chance of being sliced apart by crossover!

Step 3: Effect of Point Mutation Disruption

For schema H to survive mutation, all o(H) of its fixed bits must avoid being flipped. Since each bit survives mutation with probability (1 - p_m):

S_m = (1 - p_m)^o(H) approx 1 - o(H) * p_m (for small p_m)

Conclusion: Schemata with low order o(H) (few defined bits) have maximum survival probability!

The Fundamental Schema Theorem:

m(H, t+1) >= m(H, t) * [ f(H, t) / avg_f(t) ] * [ 1 - p_c * (delta(H) / (L - 1)) ] * [ 1 - o(H) * p_m ]

The Building Block Hypothesis & Deceptive Problems

The Building Block Hypothesis: Genetic algorithms perform search by identifying short, low-order, above-average schemata (called Building Blocks), exponentially amplifying them, and recombining them through crossover into globally optimal solutions.

Deceptive Problems: Problems where short, low-order building blocks lead evolution toward a local maximum that is completely isolated from the global optimum.

Deceptive Trap: Schema (0 * * *) has high average fitness → Population converges to (0 0 0 0) [Local Max] Isolated Peak: (1 1 1 1) [Global Max] has zero partial reward → Missed completely!

5Classifier Systems, Genetic Programming & Artificial Life

Luger 12.2–12.3: Holland's Learning Classifier Systems, Bucket Brigade credit assignment, Koza's GP trees, Conway's Life, and Cellular Automata

Real-World Intuition: Credit Assignment in a Free Market

Imagine an assembly line manufacturing luxury cars. The final worker attaches the hood ornament, and the customer pays 100,000 dollars. Should that final worker receive the entire 100,000 dollars?

Of course not! If they did, the workers who forged the engine and welded the chassis would starve and quit, and no more cars could ever be built.

In complex multi-step AI problems (like playing chess or navigating a maze), hundreds of actions occur before a reward is received. Holland's Bucket Brigade Algorithm solves this credit assignment dilemma by treating rules like merchants in an economy: every rule pays a bid to the earlier rule that set up its opportunity, and receives payment from the rule that follows it!

1. Learning Classifier Systems (LCS) & The Bucket Brigade Algorithm

[Sensory Inputs] ──► [Message List] ◄── [Classifiers Post Messages] │ ▼ ┌───────────────────────────────┐ │ Classifiers Match Conditions │ │ Make Bids based on Strength │ └──────────────┬────────────────┘ │ ▼ [Highest Bidder Wins] │ ┌────────────────┴────────────────┐ ▼ ▼ [Pays Bid to Precursor] [Takes Action / Receives Env Payoff]
  • Classifiers: Production rules of the form Condition → Action using alphabet {0, 1, #}.
  • Bidding Mechanism: Active classifier C_i makes a bid B_i = c * S_i * Specificity_i, where c is a constant, S_i is strength, and specificity is the fraction of non-# bits.
  • Payment: The winning rule pays its bid B_i to the precursor rule that posted the message that activated it.
  • Payoff: If the action satisfies the external environment, a massive reward R is added directly to the winning rule's strength. Over time, wealth flows backward along successful reasoning chains!
  • Analogy to Neural Networks: The Bucket Brigade algorithm propagates credit backwards through temporal rule sequences exactly like Backpropagation propagates error backwards through neural layer weights!

2. Genetic Programming (John Koza)

Instead of evolving fixed-length bit strings, Genetic Programming (GP) directly evolves executable computer programs, represented as LISP syntax parse trees!

LISP Program Parse Tree: (* (+ X 3) (SIN X)) [*] / \ [+] [SIN] / \ | [X] [3] [X] Terminal Set: {X, 3, Y, Constant} Function Set: {+, -, *, /, SIN, COS, SQRT}

Subtree Crossover in Genetic Programming:

Pick a random node in Parent 1 and a random node in Parent 2. Swap the entire subtrees rooted at those nodes!

3. Artificial Life & Conway's "Game of Life"

A 2D infinite grid of binary cells (Live = 1, Dead = 0). Time advances in discrete ticks governed by 4 simple rules:

  1. Survival: A live cell with 2 or 3 live neighbors lives to the next generation.
  2. Death by Underpopulation: A live cell with fewer than 2 live neighbors dies.
  3. Death by Overpopulation: A live cell with more than 3 live neighbors dies.
  4. Birth: A dead cell with exactly 3 live neighbors becomes a live cell.

4. Crutchfield & Mitchell: Emergent Particle Computation

Crutchfield and Mitchell (1995) evolved 1D Cellular Automata (CA) using genetic algorithms to solve the Density Classification Task (rho_c = 1/2):

  • Task: If initial lattice has > 50 percent ones, entire lattice must synchronize to all ones; if < 50 percent ones, synchronize to all zeros.
  • Constraint: Each cell has radius r = 3 (can only communicate with its 7 immediate neighbors; no central coordinator exists).
  • Emergent Phenomenon: The GA discovered local rules that generated coherent spatio-temporal domains. The boundaries between domains acted as physical particles (alpha, beta, gamma, delta). These particles collided and performed logic computations across space, proving that global computation emerges from simple local rules!

Luger Exercise 1: Balancing Diversity & Skill Preservation Theoretical Analysis

Problem: "The genetic algorithm is intended to support the search for genetic diversity along with the survival of important skills for a problem domain. Describe how different genetic operators simultaneously support both these goals."

Step-by-Step Solution
  • Crossover (Exploitation / Skill Preservation): Crossover acts as the primary builder. It preserves high-fitness genetic schemata (skills) discovered by separate parents and juxtaposes them into offspring. By operating at low to moderate disruption, it amplifies successful building blocks.
  • Mutation (Exploration / Diversity Maintenance): Mutation acts as an insurance policy. It injects fresh genetic alleles that were either never present in the initial population or lost due to selection. It prevents premature convergence by continually nudging the search away from local optima.
  • Selection Pressure & Elitism: Elitism guarantees the retention of the best skills (zero loss of the champion), while linear rank or tournament selection preserves diversity by assigning non-zero survival probabilities to lower-fitness exploratory candidates.
Luger Exercise 2: Inductive Bias in Representation Design Search Space Topology

Problem: "Discuss the problem of designing representations for genetic operators to search for solutions in different domains. What is the role of inductive bias here?"

Step-by-Step Solution

Inductive Bias is the set of fundamental assumptions an algorithm makes about the target concept before seeing the data. In Genetic Algorithms, the inductive bias is established almost entirely by the chromosome representation:

  • Linear Adjacency Bias: Standard crossover assumes that genes positioned close to each other on the chromosome string belong to the same functional building block (low defining length delta(H)). If two interdependent genes are placed at opposite ends of a string, standard crossover will continuously tear them apart.
  • Domain Legality Bias: In permutation problems (like TSP), a binary integer representation exhibits a catastrophic bias because standard crossover yields illegal states. An order-based representation (OX, PMX) biases the search toward valid permutation neighborhoods.
Luger Exercise 3: CNF Disjunct Bias & Alternative Fitness Metrics Constraint Satisfaction

Problem: "Consider the CNF-satisfaction problem of Section 12.1.3. How does the number of disjuncts in the CNF expression bias the solution space? Can you design another fitness measure?"

Step-by-Step Solution
  1. Disjunct Count Bias: In CNF, each clause is a disjunction (A or B or C). A clause with 10 literals is satisfied by almost any random assignment (1 - 2^(-10) = 99.9 percent satisfaction probability). A clause with only 1 literal (a unit clause) is satisfied with only 50 percent probability. Therefore, clauses with few literals exert an enormous inductive constraint on the search space.
  2. Alternative Continuous Fitness Measure: Instead of a coarse integer count of satisfied clauses (0, 1, 2, 3, 4, 5), award partial credit inside unsatisfied clauses:
    f(chromosome) = Sum of [ if clause j satisfied then 1.0 else max literal credit in clause j ] for all clauses j in Clauses
    This creates a smooth gradient landscape that prevents flat plateaus!
Luger Exercise 7: Gray Coding & Hamming Cliffs Binary Encoding Pitfalls

Problem: "Discuss the role of techniques such as Gray coding for shaping the search space of the genetic algorithm. Describe two other areas where similar techniques are important."

Step-by-Step Solution

In standard binary encoding, adjacent numbers often require flipping multiple bits. Moving from 7 to 8 requires flipping 4 bits:

7 = 0111 (binary) <---> 8 = 1000 (binary) (Hamming Distance = 4)
This is a Hamming Cliff. For a mutation operator with p_m = 0.01, the probability of taking this single step is 10^(-8), turning a tiny numerical step into an insurmountable chasm.

Gray Coding ensures that any two consecutive integers differ by exactly one single bit (7 = 0100 in gray code, 8 = 1100 in gray code, Hamming distance = 1).

Two Other Areas Where Gray Coding is Vital:

  1. Rotary Optical Encoders: Used in robotics and aircraft instrumentation to measure shaft angles without digital glitch errors.
  2. Digital Communications & QAM: In Quadrature Amplitude Modulation, mapping constellation symbols using Gray code ensures that a single-level noise burst causes only a single-bit demodulation error.

Luger Exercise 11: Constraints of Genetic Programming GP Limits

Problem: "Discuss the constraints on using genetic programming techniques. For example, what components of a solution cannot be evolved within the genetic programming paradigm?"

Step-by-Step Solution
  1. Closure Constraint: Every function in the function set must accept as arguments any data type that can be returned by any other function or terminal. Division must be protected (div(x, 0) = 1) to prevent runtime crashes.
  2. Sufficiency Constraint: If the primitive function and terminal sets do not contain the fundamental mathematical operators needed to model the system (e.g., trying to model periodicity without trigonometric operators), GP can never evolve the solution.
  3. Code Bloat: As generations advance, parse trees expand aggressively with redundant neutral code (e.g., (+ X (- Y Y))), consuming exponential RAM without improving fitness.
