1Master Exam Execution Roadmap

The strict multi-tool execution order to survive the DAV Lab Midterm

The Data Analysis & Visualization (DAV) lab midterm tests four fundamentally distinct environments: Python Requests & Nested JSON parsing, PySpark on Databricks (Medallion Architecture & Delta Lake), Advanced Pandas Hierarchical Multi-Indexing, and Microsoft Power BI (Power Query ETL, Star Schema Modeling, and DAX). Students fail not because the code is impossible, but because they execute steps out of order — inferring schemas dynamically when drift occurs, averaging pre-aggregated ratios in DAX, or slicing unsorted MultiIndexes.

⚡ The 5-Phase Sequential Lab Exam Pipeline
PHASE 01REST API & JSON

PHASE 02DATABRICKS BRONZE

PHASE 03SILVER UPSERT
DeltaTable.merge()
PHASE 04PANDAS MULTIINDEX
IndexSlice & Reshape
PHASE 05POWER BI DASHBOARD
PQ ETL → Star → DAX
Why order and strict typing are non-negotiable: In distributed Spark engines and analytical BI models, downstream operations inherit the mathematical and structural contracts of upstream steps. If you allow Spark to infer a schema on mixed JSON, your ingestion crashes. If you calculate an average discount column and then take its average in Power BI, you commit the Simpson’s Paradox / Ratio Fallacy. You must follow the exact sequential rules outlined below.

Golden Rules for the DAV Lab Exam

  • Rule 1 (Never Trust Inferred JSON Schemas): When reading API or clickstream JSON in Spark, always define an explicit StructType. If a field contains mixed types (nested object on Day 1, error string on Day 2), force it to StringType() in Bronze and extract fields safely downstream using get_json_object().
  • Rule 2 (Delta Lake Modes Matter): Use mode("overwrite") ONLY for initial full table creation or static Gold summary reports. For incremental batch updates, use mode("append") in Bronze and merge() (Upsert) in Silver to prevent duplicating historical primary keys.
  • Rule 3 (MultiIndexes MUST be Lexicographically Sorted): In Pandas, never attempt range slicing (e.g. pd.IndexSlice[:, '21730':'22752', :]) on an unsorted index. It will throw an immediate UnsortedIndexError. Always call .sort_index() first.
  • Rule 4 (Measures Over Calculated Columns in DAX): Never calculate ratios (like Profit Margin or Unit Price) as row-level calculated columns and then aggregate them with AVERAGE(). An average of ratios is mathematically invalid. Always create dynamic DAX measures using DIVIDE(SUM(Numerator), SUM(Denominator)).
  • Rule 5 (Continuous Calendar Dimension is Mandatory): Time intelligence and monthly trend lines in Power BI require an official Date table marked as such, with text month names explicitly sorted by an integer Month Number to prevent alphabetical sorting ("Apr", "Aug", "Dec").

  3. Launch Power BI Desktop and verify the Excel/CSV connector is responsive.

  • The exam spans 4 toolsets: Python API $\rightarrow$ PySpark Medallion $\rightarrow$ Pandas MultiIndex $\rightarrow$ Power BI.
  • Explicit typing prevents schema drift crashes in Spark; lexicographical sorting prevents slice crashes in Pandas.
  • In Power BI, clean in Power Query, model 1-to-many star relationships, and use dynamic DAX measures.

Step 1 & 2: Fetching API Data & Top-Level Schema Inspection

Never call response.json() without checking response.status_code first. If the endpoint returns a 404 (Not Found) or 500 (Internal Server Error), parsing raw HTML error text as JSON will crash your script.

Step 1 & 2 Exam Code: API Request & Schema Inspector
import requests
import json
import pandas as pd

url = "https://randomuser.me/api/?results=10"
response = requests.get(url, timeout=10)

# STEP 1: Verify Status Code
if response.status_code != 200:
    print(f"Error: API request failed with status code {response.status_code}")
    exit()

data = response.json()

# STEP 2: Top-level Schema Inspection Function
def inspect_top_level_schema(payload):
    print(f"{'Key':<15} | {'Type':<12} | {'Details'}")
    print("-" * 50)
    for key, value in payload.items():
        v_type = type(value).__name__
        details = ""
        if isinstance(value, list):
            elem_type = type(value[0]).__name__ if len(value) > 0 else "None"
            details = f"Length: {len(value)}, First elem: {elem_type}"
        elif isinstance(value, dict):
            details = f"Sub-keys: {list(value.keys())}"
        print(f"{key:<15} | {v_type:<12} | {details}")

inspect_top_level_schema(data)

Step 3: Recursive Deep Traversal (`extract_all_keys`)

Recursive JSON Traversal

Formal Statement: A function $f(x)$ that inspects object $x$: if $x$ is a dictionary, $f$ adds all keys to a global set and recursively calls $f(v)$ for each value $v$; if $x$ is a list, $f$ calls $f(i)$ for each item $i$ in the list.

Intuitive One-Liner: Drills down through infinite layers of Russian nesting dolls (dicts inside lists inside dicts) and brings back a list of every single field name.

Step 3 Exam Code: Universal Recursive Key Extractor
def extract_all_keys(obj, key_set=None):
    if key_set is None:
        key_set = set()
    
    if isinstance(obj, dict):
        for k, v in obj.items():
            key_set.add(k)
            extract_all_keys(v, key_set)
    elif isinstance(obj, list):
        for item in obj:
            extract_all_keys(item, key_set)
            
    return key_set

unique_keys = sorted(list(extract_all_keys(data)))
print(f"Total Unique Keys Found: {len(unique_keys)}")
print("Sample Keys:", unique_keys[:10])

Step 4 & 5: Flattening with `json_normalize` & Safe Subset Selection

pd.json_normalize() unpacks nested dictionaries into dotted or underscored column names (e.g., {"location": {"city": "Lahore"}} becomes location_city). In production and exams, APIs frequently omit null keys. If you write df[['name_first', 'email', 'missing_col']], Pandas will raise a KeyError. You must use defensive list comprehensions.

Step 4 & 5 Exam Code: Normalization & Safe Column Selection
# STEP 4: Flatten the results array with underscore separator
df_users = pd.json_normalize(data['results'], sep="_")
print(f"DataFrame Shape: {df_users.shape}")

# STEP 5: Defensive Column Selection (Crash-Proof)
desired_columns = [
    'name_first', 'name_last', 'email', 
    'phone', 'location_city', 'location_country'
]

# Error handling requirement: Only select columns that actually exist
available_cols = [col for col in desired_columns if col in df_users.columns]
missing_cols = set(desired_columns) - set(available_cols)

if missing_cols:
    print(f"Warning: Missing columns from payload: {missing_cols}")

df_contacts = df_users[available_cols].copy()
print(df_contacts.head())

Step 6: Transformation, Multi-Condition Filtering & Export

Step 6 Exam Code: Business Logic & CSV Export (DummyJSON Example)
# Fetch 30 products from DummyJSON
res_prod = requests.get("https://dummyjson.com/products?limit=30").json()
df_prod = pd.json_normalize(res_prod['products'])

# Calculate discounted price formula: price * (1 - discountPercentage / 100)
df_prod['discounted_price'] = (
    df_prod['price'] * (1 - (df_prod['discountPercentage'] / 100))
).round(2)

# Multi-condition boolean filtering:
# 1. category is 'beauty' OR 'smartphones'
# 2. rating >= 4.5
# 3. stock > 0
cond_category = df_prod['category'].isin(['beauty', 'smartphones'])
cond_rating   = df_prod['rating'] >= 4.5
cond_stock    = df_prod['stock'] > 0

df_filtered = df_prod[cond_category & cond_rating & cond_stock].copy()

# Summary Aggregation by Category
df_summary = df_filtered.groupby('category').agg(
    total_products=('id', 'count'),
    avg_price=('price', 'mean'),
    avg_rating=('rating', 'mean'),
    total_stock=('stock', 'sum')
).reset_index()

# Export both outputs to CSV
df_filtered.to_csv("filtered_products.csv", index=False)
df_summary.to_csv("category_summary.csv", index=False)
print("Files exported successfully!")
Common Student Mistake in Lab 2
Writing bitwise boolean conditions in Pandas without parentheses: df_prod[df_prod['rating'] >= 4.5 & df_prod['stock'] > 0] will fail with a TypeError because Python evaluates bitwise & with higher precedence than comparison operators. Always wrap each individual condition in parentheses: (cond1) & (cond2).

Topic 2 Recap

  • extract_all_keys uses recursion on dicts (iterate items) and lists (iterate elements).
  • pd.json_normalize(data, sep='_') flattens nested dicts into underscore columns.
  • Select subsets using list comprehension [c for c in target if c in df.columns] to prevent KeyErrors.

Step 1 & 2: Databricks Setup & Explicit Schema DDL

In Databricks, APIs like DummyJSON return fields like discountPercentage as integers (e.g. 15) for some products and floating-point decimals (e.g. 10.5) for others. If you let Spark infer schema automatically, it can fail or corrupt data types. You must define an explicit StructType.

Step 2 Exam Code: Defining Explicit Schema-on-Read
import json
from pyspark.sql.types import (
    StructType, StructField, IntegerType, StringType, 
    DoubleType, ArrayType, MapType
)
from pyspark.sql.functions import col, lit, current_timestamp, round, when, count, avg, sum as _sum

# Define explicit schema to handle mixed int/double types
product_schema = StructType([
    StructField("id", IntegerType(), True),
    StructField("title", StringType(), True),
    StructField("category", StringType(), True),
    StructField("price", DoubleType(), True),
    StructField("discountPercentage", DoubleType(), True), # Mixed int/float in source
    StructField("rating", DoubleType(), True),
    StructField("stock", IntegerType(), True),
    StructField("brand", StringType(), True),
    StructField("availabilityStatus", StringType(), True),
    StructField("minimumOrderQuantity", IntegerType(), True)
])

# Read raw file or array into Spark DataFrame
with open("/Volumes/workspace/default/products/products.json") as f:
    raw_json = json.load(f)

products_list = raw_json["products"]
bronze_raw_df = spark.createDataFrame(products_list, schema=product_schema)
bronze_raw_df.printSchema()

Step 3: Writing the Bronze Delta Table

The Bronze layer must never destroy incoming raw data. It stores raw payloads along with two mandatory audit columns: ingestion_time (when it arrived) and source (where it came from).

Step 4: Silver Layer — Data Cleansing & Quality Filtering

In Silver, you select relevant attributes, standardize naming to snake_case, enforce numeric types, apply business validation filters, and calculate derived fields.

Step 4 Exam Code: Silver Cleansing & Quality Filtering
silver_df = (
    spark.table("bronze_products")
    .select(
        col("id").cast("integer").alias("product_id"),
        col("title"),
        col("category"),
        col("brand"),
        col("price").cast("double"),
        col("discountPercentage").cast("double").alias("discount_percentage"),
        col("rating").cast("double"),
        col("stock").cast("integer"),
        col("ingestion_time")
    )
    # Business Data Quality Filters:
    .filter(col("price") > 0)
    .filter((col("rating") >= 0) & (col("rating") <= 5))
    .filter(col("stock") >= 0)
    # Business Calculations:
    .withColumn("discounted_price", round(col("price") * (1 - col("discount_percentage") / 100), 2))
    .withColumn(
        "stock_status",
        when(col("stock") == 0, "Out of Stock")
        .when(col("stock") < 20, "Low Stock")
        .otherwise("In Stock")
    )
)

# Save Cleansed Silver Table
silver_df.write \
    .format("delta") \
    .mode("overwrite") \
    .saveAsTable("silver_products")

display(spark.table("silver_products").limit(5))

Step 6: Day 2 Incremental Ingestion & Delta Lake Upsert (`MERGE`)

Delta Lake Upsert (`MERGE INTO`)

Formal Statement: A single atomic operation that joins incoming batch data with an existing Delta table on a matching primary key: rows that match are updated with new values (whenMatchedUpdateAll), and rows that do not match are inserted as new records (whenNotMatchedInsertAll).

Intuitive One-Liner: Updates old records that changed and inserts brand new records, guaranteeing zero duplicate primary keys.

Step 6 Exam Code: Bronze Append & Silver MERGE Upsert
from delta.tables import DeltaTable

# 1. Simulate Day 2 Incoming Batch (contains new IDs 195-198 AND updated IDs 1, 2)
# Convert day2_data list to Spark DataFrame
day2_df = spark.createDataFrame(day2_data) \
    .withColumn("ingestion_batch", lit("day2")) \
    .withColumn("ingestion_time", current_timestamp())

# 2. Append to Bronze Table (Bronze stores all historical events!)
day2_df.write \
    .format("delta") \
    .mode("append") \
    .saveAsTable("bronze_incremental_products")

# 3. Clean Day 2 batch before Silver Merge
day2_cleaned_df = (
    day2_df
    .filter(col("price") > 0)
    .filter((col("rating") >= 0) & (col("rating") <= 5))
    .filter(col("stock") >= 0)
    .withColumn("product_id", col("id").cast("integer"))
    .withColumn("discount_percentage", col("discountPercentage").cast("double"))
    .withColumn("discounted_price", round(col("price") * (1 - col("discountPercentage") / 100), 2))
    .select("product_id", "title", "category", "brand", "price", 
            "discount_percentage", "discounted_price", "rating", "stock", "ingestion_time")
)

# 4. Execute the Atomic MERGE Upsert into Silver
silver_target_table = DeltaTable.forName(spark, "silver_incremental_products")

(
    silver_target_table.alias("tgt")
    .merge(
        day2_cleaned_df.alias("src"),
        "tgt.product_id = src.product_id"
    )
    .whenMatchedUpdateAll()
    .whenNotMatchedInsertAll()
    .execute()
)

# 5. Verification Query: Zero Duplicates Allowed!
print("Duplicate Verification:")
spark.sql("""
    SELECT product_id, COUNT(*) AS occurrences
    FROM silver_incremental_products
    GROUP BY product_id
    HAVING COUNT(*) > 1
""").show()
Expected Row Count Logic in Lab 3 Exam
Suppose Day 1 has 194 products. Day 2 brings 6 products: 4 brand new products (IDs 195–198) and 2 updates to existing products (IDs 1 and 2).
  • Bronze Count: $194 + 6 = 200$ rows (Append mode keeps everything, including duplicate historical snapshots).
  • Silver Count: $194 + 4 = 198$ rows (Upsert merges IDs 1 and 2 in place, inserting only the 4 new IDs).

Topic 3 Recap

  • Bronze preserves raw records with ingestion_time; Silver enforces types, cleans, and deduplicates.
  • Define explicit StructType to avoid mixed int/double type mismatch in JSON.
  • Bronze uses mode("append"); Silver uses DeltaTable.merge() with whenMatchedUpdateAll and whenNotMatchedInsertAll.

Workflow 3 • Handling Corrupted Ingestion Schema Drift get_json_object

In production data pipelines, upstream producers frequently break contracts. A field that was previously a JSON dictionary (e.g. {"metadata": {"os": "android"}}) suddenly arrives as a raw string error message (e.g. {"metadata": "connection_error"}). This is known as Schema Drift. If you rely on default schema inference, your pipeline crashes. You must implement a Schema-on-Read Defense, clean the data in Silver, and execute distributed joins for the Gold layer.

Step 1 & 2: The Schema Trap & Schema-on-Read Defense

If you run spark.read.json("/raw_clicks/") on folders containing both Day 3 (metadata is Struct) and Day 4 (metadata is String), Spark throws AnalysisException: Since Spark 2.3, the queries on raw JSON datasources fail when conflicting types are found. The Defense: Explicitly define metadata as StringType() in a StructType. Spark will read the JSON object as a literal stringified JSON, avoiding the crash.

Step 2 Exam Code: Schema-on-Read Defense for Bronze Clicks
from pyspark.sql.types import StructType, StructField, StringType
from pyspark.sql.functions import col, upper, current_timestamp, get_json_object, count
import matplotlib.pyplot as plt

# Explicit schema: metadata is STRICTLY read as StringType!
click_schema = StructType([
    StructField("event_id", StringType(), True),
    StructField("user_id", StringType(), True),
    StructField("action", StringType(), True),
    StructField("metadata", StringType(), True),  # Neutralizes Struct vs String conflict!
    StructField("timestamp", StringType(), True)
])

# Read directory containing both day3.json and day4.json
bronze_clicks = (
    spark.read
    .schema(click_schema)
    .json("/Workspace/Users/[your_email]/raw_clicks/")
)

bronze_clicks.write.format("delta").mode("overwrite").saveAsTable("bronze_clicks")
display(spark.table("bronze_clicks"))

Step 4: Silver Clicks — Handling Stringified JSON & Bot Filtering

PySpark `get_json_object` Function

Formal Statement: get_json_object(col, path) evaluates a JSON path expression (e.g. "$.os") against a column containing a stringified JSON payload.

Intuitive One-Liner: Safely pulls a nested key out of a stringified JSON block; if the string is corrupt or missing (like "connection_error"), it gracefully returns null instead of crashing the job.

Step 4 Exam Code: Filtering Bots & Safe JSON Extraction
silver_clicks = (
    spark.table("bronze_clicks")
    # 1. Filter out bot crawlers (user_id containing 'bot')
    .filter(~col("user_id").contains("bot"))
    # 2. Boolean flag: True if action is checkout
    .withColumn("is_checkout", col("action") == "checkout")
    # 3. Extract the 'os' key from the stringified metadata column
    .withColumn("os", get_json_object(col("metadata"), "$.os"))
)

silver_clicks.write.format("delta").mode("overwrite").saveAsTable("silver_clicks")

Step 1 & 2: Setup, Data Cleaning & MultiIndex Construction

In UCI Online Retail data, orders with InvoiceNo starting with "C" represent cancellations with negative quantities. They must be isolated into a separate DataFrame so they do not distort sales revenue.

Step 1 & 2 Exam Code: Setup, Hygiene & GroupBy MultiIndex
import pandas as pd
import numpy as np

# Load retail CSV
df = pd.read_csv("online_retail.csv")

# STEP 1: Parse Datetimes and Create Derived Calendar Attributes
df['InvoiceDate'] = pd.to_datetime(df['InvoiceDate'])
df['Date'] = df['InvoiceDate'].dt.date
df['Month'] = df['InvoiceDate'].dt.strftime('%Y-%m')

# Isolate cancellations (InvoiceNo starting with 'C')
df_cancelled = df[df['InvoiceNo'].astype(str).str.startswith('C')].copy()
df_clean = df[~df['InvoiceNo'].astype(str).str.startswith('C')].copy()

# Add Revenue measure
df_clean['Revenue'] = df_clean['Quantity'] * df_clean['UnitPrice']

# STEP 2: Build Monthly Summary with 3-Level MultiIndex
summary_monthly = df_clean.groupby(['Country', 'StockCode', 'Month']).agg(
    TotalQty=('Quantity', 'sum'),
    TotalRevenue=('Revenue', 'sum')
)

# Confirm and set level names
summary_monthly.index.set_names(['Country', 'StockCode', 'Month'], inplace=True)
print("Index Levels:", summary_monthly.index.nlevels)
print("Level 0 Values:", summary_monthly.index.get_level_values(0).unique()[:5])

Step 3: Exposing Missing Sales with `from_product` & `reindex`

Cartesian Grid Reindexing (`from_product`)

Formal Statement: pd.MultiIndex.from_product([A, B, C]) generates the full Cartesian product $A \times B \times C$. Reindexing an existing aggregated DataFrame against this grid reveals combinations where no transaction occurred.

Intuitive One-Liner: GroupBy silently ignores items that didn't sell in a given country and month; from_product forces those missing combinations to appear explicitly with a revenue of 0.

Step 3 Exam Code: Full Grid Reconstruction
countries = df_clean['Country'].unique()
stockcodes = df_clean['StockCode'].unique()
months = df_clean['Month'].unique()

# Generate complete Cartesian grid
full_grid = pd.MultiIndex.from_product(
    [countries, stockcodes, months],
    names=['Country', 'StockCode', 'Month']
)

# Reindex and fill missing sales with 0
summary_complete = summary_monthly.reindex(full_grid, fill_value=0)
print(f"Original GroupBy Rows: {len(summary_monthly)}")

Step 4 & 5: Slicing (`IndexSlice`, `.xs`) & The Sorting Trap

The Critical Lexicographical Sorting Trap
If you attempt to slice an unsorted MultiIndex using a range (e.g. '21730':'22752'), Pandas will crash with: UnsortedIndexError: 'Key length (3) was greater than MultiIndex sort depth (0)'. Pandas requires sorted indexes for range slicing. You must run summary.sort_index(inplace=True) and verify summary.index.is_monotonic_increasing!

summary_monthly.sort_index(inplace=True)
assert summary_monthly.index.is_monotonic_increasing

Step 7: Level-wise Analysis & Revenue Share with `transform()`

Step 7 Exam Code: Group-Level Share & Best-Seller per Country
# Calculate what % of each country's monthly revenue came from each product
# transform('sum') broadcasts the monthly country total back to every product row
monthly_country_total = summary_monthly.groupby(
    level=['Country', 'Month']
)['TotalRevenue'].transform('sum')

    summary_monthly['TotalRevenue'] / monthly_country_total
).fillna(0)

# Find the single product with highest revenue share in Dec 2010 per country

Topic 5 Recap

  • pd.MultiIndex.from_product() reveals missing sales skipped by standard groupby.
  • Always call df.sort_index() before range slicing with pd.IndexSlice.
  • .xs(key, level='...', drop_level=...) extracts cross-sections across inner levels.
  • unstack() pivots inner row index to columns; stack() reverses it.
  • groupby(level=...)['Revenue'].transform('sum') aligns group totals back to individual rows for percentage shares.

Phase 5: DAX Measures vs Calculated Columns

Calculated Column vs DAX Measure

Calculated Column: Stored in memory per row when data loads. Never aggregates dynamically.

DAX Measure: Dynamic mathematical formula evaluated on-the-fly depending on the active filter context (slicers, drill-downs).

Phase 5 Exam DAX: 6 Core Business Measures
-- 1. Total Sales
Total Sales = SUM(Sales[Sales])

-- 2. Total Profit
Total Profit = SUM(Sales[Profit])

-- 3. Total Quantity
Total Quantity = SUM(Sales[Quantity])

-- 4. Total Distinct Orders
Total Orders = DISTINCTCOUNT(Sales[OrderID])

-- 5. Average Order Value
Average Order Value = DIVIDE([Total Sales], [Total Orders], 0)

-- 6. Profit Margin (Format as Percentage with 2 decimals)
Profit Margin = DIVIDE([Total Profit], [Total Sales], 0)
The Ratio Fallacy Experiment (Lab 7 Task 1.4)
If you create a calculated column Profit per Unit = DIVIDE(Sales[Profit], Sales[Quantity]) and take its AVERAGE, you get a completely different number than measure DIVIDE([Total Profit], [Total Quantity]). Why? The column average is an unweighted mean of individual row ratios (a small $10 order with 90% margin has the same weight as a $10,000 order with 2% margin). The measure calculates total profit divided by total units, which is the true economic reality. Always use DAX measures for ratios!

Top 10 Rapid-Fire Viva Defense Questions

  1. Q: Why do we store raw data in Bronze with append mode instead of upserting immediately?
    A: Bronze represents an immutable audit log of raw ingested history. Overwriting or deduplicating in Bronze destroys replayability and forensic audit capabilities.
  2. Q: Why did we force metadata to `StringType()` in Lab 4?
    A: Day 3 had nested JSON (Struct) while Day 4 had an error string. In Spark, conflicting types cause an AnalysisException during schema inference. StringType accepts any shape safely.
  3. Q: In Power BI, when should you use a Slicer vs a Page-level filter?
    A: Slicers are interactive visual controls designed for report consumers/end-users. Page-level filters in the filter pane are intended for report authors to restrict data scope permanently.
  4. Q: What is the difference between `stack()` and `unstack()` in Pandas?
    A: unstack() pivots a row index level into wide column headers. stack() pivots column headers down into a long row index.
  5. Q: What does `margins=True` do in `pivot_table()`?
    A: It appends an "All" row and column representing grand totals across all rows and columns.
  6. Q: Why do we hide foreign keys in the Sales Fact table in Power BI?
    A: To enforce the Star Schema contract. It prevents users from accidentally dragging unlinked Fact attributes into charts instead of the validated Dimension table attributes.
  7. Q: What happens if you do not check `response.status_code` in a REST API script?
    A: If the server returns a 404 or 500 error, calling response.json() fails with a JSONDecodeError because the returned response is HTML error text.
  8. Q: How does `get_json_object` behave when given corrupted JSON?
    A: It evaluates safely to null without crashing the PySpark distributed executor task.
  9. Q: Why did we use `Reference` instead of `Duplicate` for dimension tables in Power Query?
    A: Reference creates a dependency on the cleaned Sales query. Any future cleaning applied to Sales automatically flows into the dimension tables without duplicating logic.
  10. Q: What does `transform('sum')` do in Pandas that normal `agg('sum')` cannot do?
    A: Normal agg() collapses rows to the group level. transform() calculates the group sum but retains the original DataFrame's shape, broadcasting the total back onto every row for percentage calculations.

Topic 7 Recap

  • Always defend schema drift with StructType(StringType) and get_json_object().
  • Always explain why ratio measures in DAX must use dynamic sums, avoiding the average of averages fallacy.
  • Sort MultiIndexes before slicing, and reference cleaned queries in Power BI to ensure single source of truth.

9Interactive Practice MCQs & Challenges

Test your practical understanding with immediate feedback and worked exam questions

Attempt these 10 exam-level MCQs. Each question reflects real tricky scenarios from the FAST-NU lab manuals.

1. In Lab 4, why does reading raw clickstream JSON with default Spark inference crash when Day 4 data arrives?
Spark cannot unify a nested Struct with a primitive String in the same column during automatic inference. You must enforce an explicit StructType where metadata is read as StringType().
2. In Power BI, why does taking the AVERAGE of a calculated column `Profit per Unit = DIVIDE(Sales[Profit], Sales[Quantity])` produce an incorrect figure?
This is the classic Ratio Fallacy / Simpson's Paradox. An average of row ratios treats a 1-unit order the same as a 10,000-unit order. You must always use a measure: DIVIDE([Total Profit], [Total Quantity]).
3. In Pandas, what happens if you run `df.loc[pd.IndexSlice[:, '21730':'22752', :], :]` on an unsorted MultiIndex?
Range slicing in Pandas uses binary search under the hood, which strictly requires a sorted index. Call df.sort_index(inplace=True) first.
4. When performing an incremental batch load into a Silver Delta Lake table, which operation must be used to prevent duplicate records?
overwrite destroys old data; append creates duplicate rows for updated keys. merge() updates matching keys in place and inserts new ones.
5. In Power BI, why do month names on a Line Chart sort as "Apr, Aug, Dec, Feb..." by default?
Text strings always sort alphabetically (A-Z). You must explicitly link the text month column to an integer Month Number (1-12) via Column Tools → Sort by Column.
6. Why does `pd.MultiIndex.from_product()` have significant analytical value over standard `groupby()`?
GroupBy silently omits combinations with zero records. Cartesian products force those combinations into existence so you can fill them with 0.
7. How does PySpark's `get_json_object(col, "$.os")` handle corrupted text like `"connection_error"`?
get_json_object is designed for fault tolerance; if the JSON path does not match or the payload is not valid JSON, it returns null.
8. What is the difference between a Visual-level filter and a Slicer in Power BI?
Visual-level filters restrict one specific visual (like Bottom 3 products), while slicers sit on the canvas for user interaction.
9. In Pandas, which code snippet correctly calculates the percentage share of each product within its country and month?
transform('sum') preserves the original index and broadcasts the group sum to every row in that group, allowing direct division.
10. Why must `Remove Duplicates` be executed on OrderID in Power Query during Lab 6?
Duplicate OrderIDs in sales tables represent corrupted logging and artificially inflate sales and profit totals.
